## Phase 11A reconciliation outcome (2026-09-03)

Reconciled by direct code inspection; supersedes the "completion UNKNOWN" status in MASTER_ROADMAP.md Appendix A for these three findings:

1. **Docker service deduplication — resolved as "no action required".** `src/services/dockerService.js` is a deliberate 4-line re-export shim over the canonical shared implementation `src/shared/dockerService.js` (and `agent/src/services/dockerService.js` re-exports the same shared file for the Agent package). This is the established "shared implementation + target-local shim" packaging seam, not duplication. It is verified by `docker:smoke` (asserts the Agent shim loads) and `packaging-artifact-smoke` (asserts the packaged Agent ships both paths). The only in-app runtime consumer is `src/services/serviceRouter.js`. Future audits should not flag the shims for deduplication.
2. **Shared service-framework cleanup — pattern confirmed.** Shared pure-logic modules (`src/shared/resourceOperationLifecycle.js`, `src/shared/instanceMetricsLifecycle.js`, `src/shared/publicAccessServiceRegistry.js`) carry contracts consumable by both the desktop app and the Agent, with service-layer wiring in `src/services/`. Docker follows the same pattern with the implementation side in shared.
3. **Public Access provisioning review — reviewed; documented contract and known limits.** `createPublicAccessService` (src/services/publicAccessProviderService.js) writes a registry record (state `pending-provider-setup`) and returns `success: true` meaning "record accepted", not "provider resource provisioned". Provider resources (tunnels, DNS, firewall rules) are never created directly by this service, and deletion removes only the registry record — there is no provider-side revoke/teardown path (including no firewall-rule delete counterpart). External resources created outside AnxOS are acknowledged via `not-created-by-anxos` but not cleaned up. These are documented contract limits, not regressions; closing them (rollback/compensation, provider teardown, provisioning-lifecycle integration) is V2-H scope, not V1-A.
