Features

Built for server work

AnxOS Control Center is a local-first desktop workspace for the machines you own. Add this PC or a remote AnxOS Agent node, install game servers from the Marketplace, and run the day-to-day operations from one window.

One control plane

One control plane for machines you own

Every machine AnxOS manages is a node. This PC runs Control Center with its built-in local Agent; other computers run the official AnxOS Agent and appear in the same Nodes view. The hardware, the network, and the data stay yours.

  • This PCThe computer running Control Center is managed locally. On Windows the built-in Local Agent can run as a service, so the desktop app does not need to stay open.
  • Remote Agent nodesAdd a Windows desktop or a headless Debian/Ubuntu server by installing the official AnxOS Agent there and pairing it with a one-time code.
  • Node healthThe Nodes view summarizes total, online, and offline nodes, Docker availability, connected Agent state, and health issues to review.

Add computers

Add any computer in minutes

Whether the machine sits next to you or in a rack, adding it follows the same idea: install, generate a one-time pairing code on that machine, and paste it here once. Normal setup never asks you to copy an Agent token.

Desktop computer

Install AnxOS Control Center on that PC, open Agent Control, turn on “Another computer will connect to this one”, then generate a pairing code and paste it into Pair with Code here. Both computers need to be on the same network or tailnet.

Headless server

Install the official AnxOS Agent package on Debian 11+ or Ubuntu 22.04+ x64. It runs as a systemd service with its own CLI/TUI, shows a pairing code, and appears in Nodes after you paste it here once.

Open the setup guide
Pair with Code is the recommended path

Direct Agent URL and token setup is an Advanced option for development, recovery, or older Agents — normal setup never requires it.

Marketplace

Run servers and game servers

The Marketplace installs server templates onto the node you choose, and the console, files, logs, health, and backups attach to whatever you create.

  • Minecraft Java editions and modpacksBrowse templates such as Vanilla and Paper and install them on the selected node.
  • SteamCMD titlesPalworld, Valheim, Rust, Counter-Strike 2, and Terraria.
  • FiveM — ExperimentalLabeled Experimental in the Marketplace and requires your own FiveM license key.
1 Create

Pick a template and a target node. Prepare Node makes sure the runtimes the template needs are present first.

2 Starting

The template installs and boots. Instances follows the server from starting to running.

3 Running

Console, files, logs, health, and backups are available for the running server.

Operations

Operate it day to day

Server work is more than pressing Start. These are the tools you live in once an instance exists.

Console and commands

Send commands and read the output live, on this PC or a remote Agent node. Longer jobs are tracked as background operations.

Files

Browse, edit, upload, and download instance files from the same window as the console.

Logs and diagnostics

Sanitized logs with fingerprinted credentials: diagnostics are designed to strip secrets before you read or share them.

Health and metrics

Node health, issue counts, and metrics freshness roll up on the Dashboard so problems surface early.

Backups

Back up and restore server data from the app, and keep copies on storage you control.

Updates

Check for Control Center updates inside Settings. Windows builds are code-signed; Linux packages and the Agent ship with SHA-256 checksums.

Updates stay visible

Settings › Updates shows the current version and build, the release channel, the last update check, and whether a newer release exists.

  • Signed Windows installerThe Windows installer is code-signed. Linux packages and the Agent are not code-signed and ship with SHA-256 checksums.

Public access

Reach it from anywhere, on your terms

Nothing is exposed until you set it up. Public Access shows the state of each provider so you always know what is reachable, and from where.

Playit.gg

Integrated

Create and manage the tunnel in Playit (playit.gg), then refresh AnxOS to see the current state.

Cloudflare Tunnel

Needs cloudflared

Install cloudflared on the node, then refresh Public Access in AnxOS.

Tailscale

Tailnet-only

Sign in to Tailscale on the node. Sharing stays inside your tailnet.

Port forwarding

Router-level

Manual: you configure the forward on your router and own the firewall rules.

Provider states such as stopped, not installed, and authentication required are shown directly in the app.

Local Agent

Run Everything on Your Own PC

The AnxOS Local Agent securely connects the desktop app to services running on your computer. It handles server processes, files, dependencies, backups, and networking while keeping your data on your own machine.

Normal Windows users do not need a separate Debian or Ubuntu server. The Local Agent can run as a Windows service, remote servers remain optional, authentication is configured automatically, and you can stop or uninstall it when you no longer need it.

Runs Locally

Manage servers and files on This PC without sending work to a developer-owned Debian machine.

Automatic Setup

AnxOS installs the managed Agent runtime and prepares the folders it needs from inside the app.

Starts with Windows

The Local Agent can run as a Windows service, so the desktop app does not need to stay open.

No Token Copying

Local pairing is handled automatically on your own computer without asking you to paste Agent tokens.

Remote Servers Optional

Remote nodes are optional: add another desktop or a headless Debian/Ubuntu machine whenever you need one.

Easy Repair and Updates

Agent diagnostics, repair, and updates stay inside AnxOS instead of requiring terminal commands.

Local by default

The Agent serves AnxOS on the local machine over loopback (localhost). Remote access is not enabled by default; exposure through Public Access providers is opt-in.

One-time pairing codes, no token copying

Adding a computer generates a one-time pairing code on that machine. Paste it once into Pair with Code and the node appears; normal setup never asks you to read tokens from config files.
